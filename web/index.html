BLE

Exactly 6 digits required (leading zeros allowed, e.g. 001234). With PIN enabled, unpaired devices cannot communicate — pairing with PIN is enforced. Already paired devices stay paired. Without the checkbox, pairing is accepted automatically (Just Works).
Without the checkbox, advertising slows down after 15s idle to give WiFi more airtime (BLE and WiFi share one radio). With the checkbox, advertising stays permanently at the fast interval (20-40ms) — the device is always instantly discoverable and connects fastest, but WiFi throughput may suffer.

Access Point (Fallback)

Like BLE Auto: riding above the ERPM threshold keeps the AP awake and brings it back after timeout. A connected AP client pauses the timer.

BLE Mode

Boot default: BLE on. Movement above threshold resets the idle timer. Active connection (BLE/TCP/Web-UI) pauses the timer.

Movement Detection

When BLE Auto mode or AP Auto mode is active and has switched off after the idle timeout, riding above this ERPM value switches BLE/AP back on. Higher value = needs faster riding to wake.

VESC
While VESC Tool or the app is connected, the bridge forwards all UART traffic and cannot read it for itself. With this on, the bridge sends its own COMM_GET_VALUES request so the heater keeps getting ERPM. The reply also reaches the client, which VESC Tool normally handles without trouble. Turn it off if the client misbehaves — everything else about the heater keeps working. No effect during a firmware upload through the bridge: nothing is injected while the client is talking.
Debug
Boot/reset diagnostics are always logged: power-on, software restart, panic/exception, watchdog and brownout.
-
Log Upload
Buffers all event logs (boot/reset diagnostics, WiFi and AP events with disconnect reasons, BLE, roaming, VESC link, periodic state snapshot) and pushes them to an HTTP server as soon as the home network is reachable. Byte dumps of the bridge traffic are deliberately excluded — they would flood the buffer. While WiFi is down the buffer keeps filling and everything is delivered after the reconnect. Runs independently of the debug mode above and survives a restart.
2000 lines occupy about 650 KB of PSRAM, allocated once at boot and never freed. Turn it down to save PSRAM. With "Off" there is no buffer at all — and with it no [PRE-RESET] replay and no black box delivery, because both run through this buffer.
